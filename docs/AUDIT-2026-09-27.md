# Reliability and responsiveness audit · 27 September 2026

Status: verification in progress. The fixes below are committed; the broad
browser run and production deployment must be checked before this record is
treated as a completed release receipt.

## Scope and method

The audit covers public search, walking/driving and arrival cards; globe and
campus selection; owner selection, saving, recovery and review; architectural
and mesh editing; image editing and uploads; GIS inspection; activity reporting;
offline preparation; and publication/package compatibility. Tests use isolated
fixtures and mocked authentication. Real approved photographs were separately
attached through the production owner's normal review workflow.

The starting code revision was `c504979`. The published content baseline was
`lasu-49f832190110`: 395 buildings, 220 places, 39 photographs and 121 manifest
assets totalling 19,986,835 bytes. App deployment must preserve this content;
the six new photographs remain private drafts until a separate map release.

Reproductions were checked before changes where practical. Successful unit
checks alone are not treated as browser, offline or physical-device evidence.
The local machine has 8 GB RAM. A combined software-WebGL browser run exhausted
available memory and was interrupted; broad Chromium, WebKit and PWA checks now
run on separate CI runners. Local measurements run sequentially without a
concurrent build or graphics test.

## Confirmed issues and changes

| Priority | Trigger and previous behaviour | Change and regression evidence |
| --- | --- | --- |
| High | A synchronous failure in an offline asset task leaked one of three pool slots. Repeated failures could stall every later download. | Normalize task execution through a promise and release the slot on both failure paths. A failing batch followed by a successful batch now completes. |
| High | Changing campus while authentication or a transient save retry was pending could send the retry to the new campus. | Capture campus identity before awaiting authentication and retain it throughout retries and model-asset operations. The regression previously observed `lasu, unilag`; it now observes `lasu, lasu`. |
| High | An ArcGIS layer could replace object IDs during retrieval while retaining the same record count. | Compare the final identity set as well as the count. Reject the inconsistent snapshot, reuse already-read layer metadata, and enforce the combined feature limit after each layer. |
| Medium | Each local image recipe edit rewrote source/output image bytes; opening one gallery read other galleries' bytes too. | IndexedDB version 2 stores image content separately and indexes gallery metadata. Atomic migration retains originals and outputs. Metadata patches preserve concurrent associations and do not recreate deleted drafts. |
| Medium | Repeated rotation skipped two orientations, and undo could leave a preview from a different recipe visible. | Normalize quarter turns across all four orientations; clear outdated previews and gestures when changing history. Unit and responsive image-editor workflows cover the change. |
| Medium | A status refresh notified every Activity subscriber repeatedly and replaced unchanged action callbacks. | Batch updates into one notification, retain unchanged callbacks and remove duplicate release/job cards. Idle polling is 30 seconds; active work uses five seconds. |
| Medium | Older active jobs and recently finished watched jobs could disappear outside the recent-history limit. Database row caps could also truncate an oversized active queue. | Query active and watched jobs separately from recent history, merge by identity, validate watched IDs and probe for overflow at the database cap. |
| Medium | `LASU Clinic` did not find the imported `LASU  Clinic` footprint with two spaces. | Normalize whitespace consistently for feature/entrance/street search while preserving stored names. The browser regression selects the correct building without creating an edit. |
| High | Reload protection checked saved geometry but omitted unfinished model fields and writes still queued for browser recovery. | Include both in the leave-page guard. Delayed-write unit coverage and the offline roof workflow verify protection and durable reopening. |
| Medium | The conflict alert covered the mobile panel's Apply button; all backup controls were hidden at phone widths. | Place resolution controls above their warning and retain an accessible 44px backup menu. WebKit tests resolve both conflict scenarios and download recovery. |
| Medium | Closing a survey during an in-flight save silently ignored the click. | Disable Close until the existing durability operation finishes. The two-entrance survey workflow can then close and test its route. |

No public package schema, database migration or saved-model change is required.
The image-storage upgrade is local to the browser. Locked model items, placement
limits, recovery/conflict guards and release approval remain in force.

The audit also found stale verification paths: upload tests skipped image
preparation, model tests used removed building-card controls or the former flat
part list, and full Python discovery omitted the projection dependency used by
the UNILAG downloader. Updated workflows use the workspace, nested tree and
current autosave behaviour. Camera comparisons wait for selection framing;
reload tests observe durable IndexedDB records before simulating restart. Model
file loaders are prebundled for development to avoid dependency discovery
reloading a running worker test. These changes retain checks for geometry,
neighbours, undo, failure recovery and saved drafts.

## Image-storage measurement

Five fresh Chromium contexts compare `c504979` with the new storage code using
real IndexedDB. Each context stores eight independent 2 MiB source images in
different building galleries, opens one gallery and performs 20 recipe updates.
Both implementations use the same deterministic fixture bytes. These figures
measure browser storage operations, not field INP or physical disk writes.

| Measurement | Before | After |
| --- | ---: | ---: |
| Selected-gallery read, median | 45.6 ms | 5.7 ms |
| Recipe update, median | 10.7 ms | 0.6 ms |
| Recipe update, pooled p95 | 21.7 ms | 1.4 ms |
| Image bytes included in 20 metadata writes | 40 MiB | 0 |

[All five runs and individual samples](image-storage-performance-2026-09-27.json).
Migration tests compare the exact original/output bytes and preserved recipes.
The first exploratory run was slower under background work; the table uses the
sequential repeat, not the more favourable percentage from that first run.

Opening a gallery still loads that gallery's retained originals. A long-lived
gallery containing many large local images remains a memory-pressure risk even
though new import batches are bounded. Loading only the selected original is a
useful follow-up; the current improvement does not claim constant memory use.

## Existing workflow performance rechecked

The core benchmark uses the pinned historical `lasu-286bae3c6016` fixture, with
420 buildings and 220 places, to retain comparability. Cached metadata validation
and delta encoding measured 0.97–1.90 ms versus 170–210 ms for full validation.
Its serialized worker reply is 74,633 bytes instead of 2,821,381 bytes. These are
checks of existing optimizations, not gains introduced by this audit.
[Raw core measurements](core-performance-2026-09-27.json).

The production photo harness exercises five viewport sizes in both themes,
200% equivalent reflow, mobile keyboard sizing, a 200-item private library and
a 20-image upload batch with a failure and retry. The upload test now explicitly
prepares its images before changing selection; processing remains sequential and
the original building assignment is retained.

The photo interaction benchmark passed all existing 100/200 ms lab targets:
caption/selection/tab p95 was 15.9/15.3/18.2 ms on desktop and
38.6/42.3/66.1 ms with a mobile viewport and 4× CPU throttling.
[Photo interaction samples](photo-performance-audit-2026-09-27.json).

Twenty current model-editor trials used the published 395-building package and
a separate 100-detail wall fixture. No typing trial generated a model job; all
trials left one map worker and one canvas after closing. Retained GPU counts were
consistent within each fixture (28/33 buffers and eight textures). This checks
workspace cleanup, not long-session leak freedom. It is not a rerun of the
historical implementation comparison.

| Fixture / CPU rate | Input p95 | Click p95 |
| --- | ---: | ---: |
| Published / normal | 34.7 ms | 103.6 ms |
| Published / 4× throttle | 104.3 ms | 197.5 ms |
| 100 details / normal | 39.6 ms | 112.2 ms |
| 100 details / 4× throttle | 185.4 ms | 309.4 ms |

[Model samples and resource counts](model-editor-audit-2026-09-27.json).
The dense throttled click result is slower than the 200 ms responsiveness target;
selection/property rendering deserves further profiling on physical devices.
These software-GPU samples are not evidence that every low-end phone meets that
target. No baseline model speedup is claimed for this audit.

Public startup and owner startup are close to their existing gzip budgets.
New large editing libraries should stay lazy-loaded; raising the budgets is not
the remedy. The audit retains the existing worker concurrency, asset limits,
public model budgets and frozen legacy model fixtures.

## Reproduction and limits

Use Node 22 and install dependencies in `web`:

```sh
npm test -- --maxWorkers=2
npm run lint
npm run check:configured-build
node scripts/benchmark-image-drafts.mjs
npm run test:performance
npx playwright test --timeout=120000
npx playwright test --config playwright.webkit.config.ts
npx playwright test --config playwright.photos.webkit.config.ts
npx playwright test --config playwright.pwa.config.ts
npx playwright test --config playwright.photos.pwa.config.ts
```

Run graphics projects sequentially on a software-GPU machine. The configured
build uses dummy authentication settings for measurement and must not be deployed.
Python discovery needs `scripts/requirements-data.txt`; full driver coverage uses
the separate pinned GIS container. Photo performance fixtures and reproduction
are described in [Performance](PERFORMANCE.md).

No audit can prove absence of every edge case. Physical Android/iPhone graphics,
thermal/battery behaviour, installed-PWA eviction, real mobile keyboard quirks,
outdoor GPS/compass accuracy, long field surveys and production-scale 100,000-
feature imports still require device/field evidence. Emulated viewports and
software WebGL do not substitute for those checks. Live provider outages and
licensing/footprint uncertainty remain separate from renderer correctness.
